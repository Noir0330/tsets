# Tsets Partners — Company Website

A static, multipage website for the Tsets Partners law firm, built with Next.js
16.3.1 (App Router), React 19, TypeScript, CSS Modules, and next-intl. It includes
the homepage, firm information, 5 practice areas, 9 team profiles, interviews,
and contact information. Visitors can switch between Mongolian, English, and
Chinese in the browser. Language and appearance preferences are stored in
localStorage; languages do not have separate URLs.

The website has no database, API, or server-side contact form. The contact form
constructs a `mailto:` link and opens the visitor's email client; it does not send
a message itself. Fonts, images, and video are local assets. The hosting server
does not need to run Node.js, PHP, or `next start`.

## Development and structure

```bash
pnpm install
pnpm dev
```

Development URL: <http://localhost:3000>.

- `src/app` — pages and routing.
- `src/components/layout` — navigation, footer, language, appearance, and animations.
- `src/components/sections` — content components and the contact form.
- `src/lib/i18n/messages/{mn,en,zh}.json` — translations.
- `src/lib` — contact details, team members, and interviews.
- `public` — images and video; its contents are copied into the export.
- `src/app/fonts` — local fonts.

## Build and deployment package

```bash
pnpm lint
pnpm typecheck
pnpm build
```

`next.config.ts` sets `output: 'export'`, `trailingSlash: true`, and
`images.unoptimized: true`. The finished website is in **`out/`**. For example,
`/about/` maps to `out/about/index.html`. `.next/` contains intermediate build
output and is not the deployment package for this hosting setup.

The files in `out/` are the website. The resulting server path must be
`public_html/index.html`, not `public_html/out/index.html`. Keep the server's
`.htaccess`; the exported copy does not contain cPanel's PHP configuration.
Never upload the repository, `.env*` files, private SSH keys, or `node_modules`.

```bash
pnpm deploy:package
```

This command rebuilds the website and creates **`.deploy/tsets-cpanel-static.zip`**
using the system `zip` utility. `index.html` is at the archive root. The archive
excludes `.htaccess` to preserve the server-managed version and is recreated
each time. The command does not upload anything. Git ignores `.deploy/` and
`out/`.

## Recommended manual deployment without GitHub integration

Use **explicit FTPS** for the archive transfer. Uploading each exported file
separately creates hundreds of FTP data connections and may temporarily block
the client's IP address. No GitHub connection is needed.

1. Back up the complete `public_html`, including hidden files, to a location
   outside the document root. The deployment ZIP is a copy of the new release,
   not a backup of the live server.
2. Run `pnpm lint`, `pnpm typecheck`, and `pnpm deploy:package`.
3. Create a uniquely named staging folder in `public_html`. Put a `.htaccess`
   containing `Require all denied` in that folder and verify its URL returns
   403. Upload the release ZIP there with **one FTPS transfer**.
4. Use cPanel File Manager to extract the ZIP into that staging folder. Check
   the destination path in the Extract dialog, confirm the exported file set
   and sizes, and ensure files are readable (`0644`) and folders traversable
   (`0755`). A successful dialog alone does not prove every file was extracted.
5. Move the verified website files into `public_html` using one FTPS control
   connection. Publish supporting assets first and `index.html` last. Keep old
   hashed assets until the new site is verified. Do not move the staging
   `.htaccess` or ZIP into production.
6. Verify the homepage, direct navigation and refresh on subpages, team profiles,
   articles, images, video, languages, `mailto:`, and a nonexistent URL returning
   404. Delete only obsolete website files identified from the backup, then
   remove the staging folder and ZIP. Preserve `.htaccess`, `.well-known/`,
   `.user.ini`, `php.ini`, and `cgi-bin/`.
7. To roll back, restore the backed-up files and remove any new routes that
   were absent from the backup.

The server's root `.htaccess` should retain these directives alongside the
PHP configuration block generated by cPanel:

```apache
DirectoryIndex index.html
ErrorDocument 404 /404.html
Options -Indexes
```

`Options -Indexes` prevents Apache from listing a directory when an old route's
`index.html` has been removed. This export does not require rewriting every URL
to `index.html`.

## Handover notes

- The contact form requires a working email client; it does not deliver via SMTP.
- `/template-controls/` is an exported public page for template settings.
- The project has no separate language URLs, sitemap, or robots.txt.
- The October 24, 2026 inspection verified the build: 26 HTML files, 191 files in
  total, approximately 27.56 MiB. Local file references in the exported HTML resolved.
